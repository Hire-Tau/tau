Chat channels let you ask about work and send requests to a squad from Slack,
Discord, or Telegram. Tau's concierge answers questions and can create work in the routed squad,
using its configured tools and permissions. Create a squad and
[connect its model provider](/configure/models/) before testing a conversation.

## Prepare your bot

You need permission to configure the provider's bot or app and to manage Tau
integrations and channel routing. Open **Settings → Integrations**, enable the
provider's card, and expand **Settings**. Save bot credentials in that card.

<ModeContent mode="cloud">

Use your hosted instance's public HTTPS address for the webhook receiver, not
the Cloud account page. A hosted instance still needs the bot's provider setup
and channel routing below. If a credential is marked as managed, ask your
administrator about changes to it.

</ModeContent>

<ModeContent mode="self-hosted">

The provider must be able to reach your instance over HTTPS. Use its public base
URL, including any configured path prefix, followed by the receiver path below.
An address reachable only from your computer will not receive provider webhooks.
Check [configuration](/reference/configuration/) before registering the endpoint.

</ModeContent>

### Slack

Create a Slack app for the workspace. Save its **Bot token** and **Signing secret**
in Tau's Slack card. Configure `/tau` as a slash command with this request URL:

```text
https://tau.example.com/api/webhooks/channels/slack
```

Use the same URL for **Event Subscriptions**, then subscribe to `message.channels`,
`message.groups`, `message.im`, `message.mpim`, and `app_mention` for conversation
replies and mentions. Install the app into your workspace and invite it to the
channels you want it to use.

Tau's messaging adapter uses these bot scopes:

- Commands and messages: `commands`, `chat:write`, `chat:write.public`.
- Conversation access: `channels:read`, `channels:join`, `channels:history`,
  `groups:read`, `groups:history`, `im:read`, `im:write`, `im:history`,
  `mpim:read`, `mpim:history`.
- User names, mentions, and reactions: `users:read`, `app_mentions:read`,
  `reactions:read`, `reactions:write`.
- Attachments, if used: `files:read`, `files:write`.

Reinstall the Slack app after changing its scopes. Slack's
[slash-command setup guide](https://docs.slack.dev/interactivity/implementing-slash-commands/)
explains the provider-side command form.

### Discord

Create an application and bot in the Discord Developer Portal. Save its **Bot
token**, **Application ID**, and **Public key** in Tau's Discord card. Enable the
bot's **Message Content Intent** for thread replies. Set the application's
**Interactions Endpoint URL** to:

```text
https://tau.example.com/api/webhooks/channels/discord
```

Invite it with the `bot` and `applications.commands` scopes and permissions to
send messages, use commands, send messages in threads, and create public threads.
Install the Tau CLI and set `DISCORD_BOT_TOKEN` and `DISCORD_APPLICATION_ID` in
your shell's environment to the same bot and application you saved in Tau. Then
register the commands:

```sh
tau discord register
tau discord status
```

These commands call Discord directly; they do not read credentials from your
Tau integration card. Set `DISCORD_GUILD_ID` as well if you want to register
commands in one server instead of globally.

Discord verifies the interactions endpoint using the application public key.
See its [interactions documentation](https://docs.discord.com/developers/interactions/receiving-and-responding)
if endpoint verification fails.

### Telegram

Create a bot through **@BotFather**. Save its **Bot token** in Tau's Telegram card,
along with a separately generated **Webhook secret**. Use the numeric prefix of
the bot token, before the colon, for **Bot ID**.

Register `https://tau.example.com/api/webhooks/channels/telegram` with Telegram's
[`setWebhook` method](https://core.telegram.org/bots/api#setwebhook), using that
same secret as `secret_token`. The secret must contain only letters, digits,
underscores, or hyphens and be between 1 and 256 characters. Complete provider
registration through your bot administration tooling; saving a token in Tau does
not register Telegram's webhook automatically.

The request is a POST to `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook`
with two fields: `url` set to your instance's receiver URL, and `secret_token`
set to the secret saved in Tau. A successful response has `ok: true`. Telegram's
`getWebhookInfo` method reports the registered URL and recent delivery errors.

## Route messages to a squad

In the enabled provider card, find **Channel routing** and choose **+ Add New**.

1. Enter a recognizable name.
2. Enter the **Discord server ID**, **Slack workspace ID**, or numeric **Telegram
   bot ID**, depending on the provider.
3. Select the **Default Squad** for messages arriving through this connection.
4. Optionally choose **+ Add override** and pair a specific channel or chat ID
   with another squad.
5. Choose **Create** and check the new routing entry is enabled.

The server or workspace ID identifies the provider connection. An override uses
the individual channel or chat ID. Confusing these IDs can send a message to the
default squad instead of the intended override.

## Test and continue a conversation

Send `/tau status`, then `/tau ask What is this squad working on?`. Reply to the
bot's response to continue that conversation. Slack uses native thread replies,
Discord uses threads, and Telegram uses reply-to-message. In Slack, start `/tau`
from the channel composer; use replies, rather than another slash command, to
continue an existing conversation.

If there is no reply, check the global integration switch, saved credentials,
provider webhook registration, bot access to the channel, and routing entry.
If the request arrives but the agent cannot answer, check the squad's model
provider. To send work updates into this chat, configure
[notifications](/connect/notifications/) separately.
